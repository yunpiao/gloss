# Feature Specification: 修复中文页面注解目标词汇问题

**Feature Branch**: `001-fix-lang-detection`
**Created**: 2025-12-01
**Status**: Draft
**Input**: User description: "修复中英文识别问题, 现在发现中文页面里面中文里面的英文单词有注解, 正确的应该是挑选中文的一些字增加注解"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 中文页面为中文词汇添加英文注解 (Priority: P1)

作为一个正在学习英文的中文用户，当我浏览中文网页时，我希望系统为**中文词汇**添加**英文注解**（英文翻译），而不是为页面中混杂的英文单词添加注解，这样我可以通过阅读中文内容来学习对应的英文表达。

**Why this priority**: 这是用户报告的核心问题。当前系统在中文页面上错误地为英文单词添加注解，而正确的行为应该是为中文词汇添加英文翻译注解。修复此问题是本次迭代的主要目标。

**Independent Test**: 可以通过访问任意中文网页（如百度、知乎），触发注解功能，验证系统是否为中文词汇（而非英文单词）添加英文翻译注解。

**Acceptance Scenarios**:

1. **Given** 用户在一个中文网页上, **When** 用户触发词汇注解功能, **Then** 系统应为中文词汇添加英文翻译注解，而非为英文单词添加注解
2. **Given** 用户在一个中文网页上且页面包含英文单词（如品牌名、技术术语）, **When** 用户触发词汇注解功能, **Then** 系统应忽略英文单词，只为中文词汇添加英文注解
3. **Given** 用户在一个中文网页上, **When** 注解显示后用户悬停在中文词汇上, **Then** 应显示该词汇的英文翻译tooltip

---

### User Story 2 - 英文页面显示中文注解 (Priority: P2)

作为一个正在学习英文的中文用户，当我浏览英文网页时，我希望看到英文词汇的中文翻译注解，帮助我理解英文内容。

**Why this priority**: 这是现有功能的保持，确保修复中文页面问题后不影响英文页面的正常功能。

**Independent Test**: 可以通过访问任意英文网页（如Wikipedia英文版），触发注解功能，验证英文词汇是否显示中文翻译。

**Acceptance Scenarios**:

1. **Given** 用户在一个英文网页上, **When** 用户触发词汇注解功能, **Then** 系统应为英文词汇添加中文翻译注解
2. **Given** 用户在一个英文网页上, **When** 注解显示后用户悬停在词汇上, **Then** 应显示该词汇的中文释义tooltip

---

### User Story 3 - 准确的语言检测 (Priority: P3)

作为用户，我希望系统能够准确识别页面的主要语言，即使页面中混合了多种语言内容。

**Why this priority**: 语言检测是注解功能的基础，但当前的字符计数方法在大多数情况下是有效的。优化检测算法是锦上添花的改进。

**Independent Test**: 可以通过访问包含混合语言内容的页面，验证系统是否正确识别主要语言。

**Acceptance Scenarios**:

1. **Given** 一个主要为中文但包含英文代码片段的技术博客, **When** 系统检测页面语言, **Then** 应正确识别为中文页面
2. **Given** 一个主要为英文但包含少量中文引用的页面, **When** 系统检测页面语言, **Then** 应正确识别为英文页面

---

### Edge Cases

- 当页面中中英文字符数量相近时，系统如何决定页面语言？
  - **处理方式**: 保持当前逻辑，中文字符数大于英文时识别为中文，否则识别为英文
- 当页面几乎没有文字内容时，系统如何处理？
  - **处理方式**: 返回 'unknown'，不进行注解处理
- 当API返回的注解格式不正确时，系统如何处理？
  - **处理方式**: 保持现有的错误处理逻辑，显示错误提示

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在检测到中文页面时，请求AI提取**中文词汇**（而非英文单词）并返回其英文翻译
- **FR-002**: 系统必须在中文页面上只为中文词汇添加英文注解，忽略页面中已有的英文单词
- **FR-003**: 系统必须在检测到英文页面时，继续请求AI返回英文词汇的中文翻译（保持现有行为）
- **FR-004**: 系统必须正确解析并显示注解，中文页面显示英文翻译，英文页面显示中文翻译
- **FR-005**: 系统必须保持现有的语言检测逻辑（基于中英文字符数量比较）

### Key Entities

- **Dictionary Entry (词典条目)**:
  - 对于中文页面: `{"中文词汇": "英文翻译"}` — 键必须是中文词汇，值是英文翻译
  - 对于英文页面: `{"英文词汇": "中文翻译"}` (保持现有格式)
- **Annotation (注解)**: 显示的词汇标注，包含主文本和翻译
- **Tooltip (提示框)**: 悬停时显示的详细翻译信息

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在中文页面触发注解后，100%的被注解词汇应为中文词汇，不应出现英文单词被注解的情况
- **SC-002**: 用户在中文页面触发注解后，注解内容应为英文翻译
- **SC-003**: 用户在英文页面触发注解后，功能表现与修复前一致，英文词汇显示中文翻译
- **SC-004**: 语言检测准确率在混合语言页面上保持90%以上（以页面主要内容语言为准）

## Assumptions

- 用户使用此工具的主要场景是：中文用户学习英文（无论在中文页面还是英文页面都希望学习英文表达）
- 当前的字符计数语言检测方法对于大多数网页是足够准确的
- API（OpenAI兼容接口）能够正确理解prompt指令，在中文页面提取中文词汇并返回英文翻译
- 现有的DOM操作和注解渲染逻辑无需修改，只需调整API请求的prompt确保提取正确的目标词汇（中文词汇而非英文单词）
